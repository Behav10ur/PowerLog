# PowerLog 2.0 — план MVP

_Обновлено: 24.09.2026_

## Суть

PowerLog 2.0 — трекер силовых и кардио-тренировок с автоматическими достижениями и AI-тренером Отисом, который работает на устройстве. Старый код — курсовая, поэтому переписываем с нуля, а из старой версии оставляем идею, вкладки, фиолетово-синий стиль и тексты.

**Входит в MVP:** запись тренировок → прогресс и графики → автоматические достижения → Отис на Foundation Models.

**Не входит:** регистрация, сообщество, видеоуроки, калькуляторы ИМТ, синхронизация с сервером. Всё это из `File.txt`, и всё это можно добавить после MVP.

**Правила работы:**

- Один этап — одна ветка `feature/...` и PR в `main`, даже если работаешь один: в истории GitHub будет видна нормальная работа.
- Этап закрыт, только когда выполнены все пункты «Готово, когда».
- Код пишешь ты, я ревьюю и подсказываю по каждому шагу.

> **Открытый вопрос:** поднимаем таргет сразу до iOS 26 (как в плане ниже) или оставляем iOS 18 и включаем Отиса только через `#available`?

## Этап 0 — Подготовка (~1 вечер)

Цель этапа — чистый проект с новой структурой, который собирается и запускается.

1. Сохрани старую версию: тег `v1-coursework` на текущем коммите. Так курсовая останется в истории, и будет что показать в формате «было → стало».
2. Вынеси `File.txt` из папки `PowerLog/`, иначе он попадает в бандл. Удали `ActivityManager.swift` и все закомментированные куски.
3. Подними Deployment Target до **iOS 26**: без него не будет Foundation Models. Включи Swift 6 language mode и убери ландшафт на iPhone. iPad либо делай нормально, либо убери из таргета.
4. Заведи структуру папок:
    - `App/` — точка входа, `RootView` с вкладками;
    - `Models/` — SwiftData-модели и enum'ы;
    - `Features/Today`, `Features/Progress`, `Features/Achievements`, `Features/Otis` — по папке на экран;
    - `Services/` — движок достижений, сервис Отиса;
    - `DesignSystem/` — градиент, стиль кнопки и карточки (сейчас градиент скопирован в 5 мест).
5. Обнови `AGENTS.md` под новый таргет и структуру.

**Готово, когда:** проект собирается на iOS 26 без предупреждений, вкладки-заглушки открываются, тег `v1-coursework` запушен.

## Этап 1 — Модель данных на SwiftData (~2 вечера)

Главное решение: храним плоский список записей, у каждой своя `Date`, а группируем по дням только при отображении. Словарь `[Date: [Activity]]` уходит, вместе с ним уходит баг с часовыми поясами.

| Тип | Вид | Поля | Зачем |
| --- | --- | --- | --- |
| `ExerciseKind` | enum | `strength` (вес × повторы), `bodyweight` (повторы), `distance` (км + время), `steps` | Задаёт единицы и вид формы ввода |
| `Exercise` | `@Model` | `id: UUID`, `name`, `kind`, `muscleGroup?`, `dailyTarget?`, `isBuiltIn`, `sets` (связь) | Единый справочник: упражнения и достижения ссылаются на одно и то же |
| `WorkoutSet` | `@Model` | `id: UUID`, `date`, `exercise`, `weight?`, `reps?`, `distance?`, `duration?`, `note?` | Один подход или одна пробежка |
| `AchievementDefinition` | struct в коде | `id: String`, `exerciseName`, `metric`, `threshold`, `tier` | Описание достижения; в базе не хранится |
| `UnlockedAchievement` | `@Model` | `definitionID`, `unlockedAt` | Храним только факт и дату получения |

Задачи:

1. Опиши модели из таблицы. Для связи `Exercise` → `sets` выбери delete rule осознанно: удалил своё упражнение — что случится с историей?
2. Добавь вычисляемое «главное значение» подхода по `kind`: вес, повторы, километры или шаги. На нём будут строиться графики и достижения.
3. Разберись с сидингом: при первом запуске в базу кладутся встроенные упражнения (старые 7 плюс «Бег»), проверка через `fetchCount`.
4. Сделай in-memory `ModelContainer` с тестовыми данными для `#Preview`: он понадобится на всех экранах.

**Готово, когда:** при первом запуске в базе появляются 8 упражнений, а превью работают на тестовых данных.

## Этап 2 — Экран «Сегодня» (~3 вечера)

Это новая «Сводка»: лента недели, тренировки выбранного дня, добавление и редактирование. Здесь закрываются баги из ревью.

1. **Лента недели.** Интервал через `.weekOfYear`, свайп или стрелки для прошлых недель, кнопка «Сегодня». При возврате из фона (`scenePhase`) неделя пересчитывается, чтобы не застревать во вчерашнем дне. Дни с тренировками отмечаются точкой. Ширины не хардкодятся.
2. **Список дня.** Через `@Query` с предикатом по диапазону дат (начало дня … начало следующего), группировка по упражнению: «Приседания — 3 подхода, 60 кг × 8». Удаление свайпом. Пустой день — через `ContentUnavailableView`.
3. **Добавление.** Выбор упражнения из базы (плюс «Создать своё»), форма подстраивается под `kind`. До ввода корректных значений «Сохранить» неактивна: никаких нулей и пустых названий. Подставляй прошлый результат по этому упражнению — это сильно ускоряет ввод.
4. **Редактирование.** Через `.sheet(item:)`, правки идут в локальный черновик, в модель пишем только по «Сохранить», так что «Отмена» правда отменяет. Удаление с подтверждением (`confirmationDialog`).
5. **Цель дня.** Если у упражнения есть `dailyTarget`, рядом показывается прогресс-бар (без деления на ноль).

**Готово, когда:** можно записать реальную тренировку за минуту, данные переживают перезапуск, экран нормально выглядит на iPhone SE и на Pro Max. С этого момента стоит пользоваться приложением самому: к этапу 3 накопятся реальные данные для графиков.

## Этап 3 — Прогресс и графики (~2–3 вечера)

Новая вкладка «Прогресс» показывает динамику по каждому упражнению. Это то место, где Swift Charts выглядят солидно в портфолио.

1. **Список упражнений** с мини-спарклайном и последним результатом. По тапу — детальный экран.
2. **Детальный график:** `LineMark` + `PointMark` по лучшему результату за день, период выбирается через `Picker` (неделя / месяц / всё время), по касанию показывается значение (`chartXSelection`). Для силовых — переключатель «Вес / Объём (вес × повторы)».
3. **Личные рекорды:** максимум, лучший объём, дата рекорда. По желанию — оценка 1ПМ по формуле Эпли: вес × (1 + повторы / 30).
4. **Недельная сводка** сверху: количество тренировочных дней и текущая серия (streak).
5. Логику агрегации (лучший за день, рекорды, серия) вынеси в отдельный `StatsService` из чистых функций, без SwiftUI. Им же потом будут пользоваться достижения и Отис, и его легко покрыть тестами.

**Готово, когда:** по любому упражнению видно график и рекорды, а `StatsService` не импортирует SwiftUI.

## Этап 4 — Автоматические достижения (~2 вечера)

Прогресс достижений больше не вводится руками: он считается из записей тренировок. Это и была недоделанная связка из курсовой.

| Тип достижения | Пример | Считается из |
| --- | --- | --- |
| Рекорд за подход | «Жим стоя 60 кг» | Максимум «главного значения» |
| Сумма за день | «100 отжиманий за день», «12 000 шагов» | Сумма за календарный день |
| Накопительное | «100 км бега всего» | Сумма за всё время |
| Серия | «7 дней подряд» | Текущая серия из `StatsService` |

1. Опиши каталог `AchievementDefinition` в коде (уровни бронза / серебро / золото вместо «Отжимания 1 / 2»). Связь с упражнением — только по идентификатору, никакого `contains` по названию.
2. `AchievementEngine`: принимает записи и уже полученные достижения, возвращает прогресс по каждому и список новых. Запускается после каждого сохранения подхода.
3. Нужно решить: если подход удалили, полученное достижение остаётся или сгорает? Проще и приятнее пользователю, если остаётся.
4. **UI:** сетка с закрытыми и открытыми достижениями (кольцевой прогресс из старой версии можно оставить), дата получения. Когда достижение открывается, показываем баннер с анимацией и хаптикой (`sensoryFeedback`).
5. Тесты на движок через Swift Testing: порог ровно достигнут, серия прерывается, полученное достижение не выдаётся второй раз.

**Готово, когда:** записал подход → достижение открылось само, ручного ввода прогресса нет, тесты зелёные.

## Этап 5 — Отис на Foundation Models (~3–4 вечера)

Отис становится on-device тренером, который видит твои данные через tool calling. Без ключей, без сервера, данные не покидают телефон. Это главная фишка проекта.

**Сначала проверь язык.** Посмотри `SystemLanguageModel.default.supportedLanguages` на своём устройстве. Если русского там нет, Отис будет отвечать по-английски, и это влияет на решение о языке всего приложения (см. этап 6).

1. **Доступность.** Проверяй `SystemLanguageModel.default.availability` и показывай понятный экран для каждой причины: устройство не поддерживается, Apple Intelligence выключен, модель ещё скачивается. Остальное приложение должно работать без Отиса.
2. **Сессия.** Одна `LanguageModelSession` на диалог — история сохраняется сама. В instructions: роль тренера, короткие ответы, отвечать только по данным из инструментов, не давать медицинских советов.
3. **Инструменты (`Tool`):** `getRecentWorkouts(days:)`, `getPersonalRecords(exercise:)`, `getAchievementProgress()`. Все идут через `StatsService` и возвращают короткий текст: окно контекста маленькое (~4K токенов).
4. **Стриминг** ответа через `streamResponse`, индикатор «Отис печатает…», блокировка кнопки во время ответа, автопрокрутка вниз. Обработка ошибок: переполнение контекста → новая сессия, guardrails → вежливый отказ.
5. **Быстрые запросы-чипы:** «Как прошла неделя?», «Что я давно не делал?», «План на завтра». Для плана используй `@Generable`-структуру (упражнение, подходы, повторы) и рисуй её карточкой с кнопкой «Добавить в день».
6. Наработки из Nucleus переноси только то, что тут реально нужно: это тренер, а не универсальный чат.

**Готово, когда:** на вопрос «как мой прогресс в приседе?» Отис отвечает реальными цифрами из базы, а на неподдерживаемом устройстве приложение не ломается.

## Этап 6 — Полировка и системные фичи (~3 вечера)

Обязательные пункты идут первыми; остальное делаешь, если останется время.

| Пункт | Обязательно? | Что сделать |
| --- | --- | --- |
| Онбординг | Да | `fullScreenCover` с нормальным биндингом, без `.constant`; 2–3 экрана, последний — выбор любимых упражнений |
| Локализация | Да | String Catalog, минимум RU + EN (для работодателей и скриншотов); даты через `.formatted()` без зашитого `ru_RU` |
| Дизайн и доступность | Да | Тёмная тема, Dynamic Type до самого крупного размера, подписи VoiceOver на графиках и кольцах прогресса, иконка приложения |
| HealthKit | Желательно | Шаги и ходьба из «Здоровья» вместо ручного ввода, только чтение |
| Виджет | Желательно | WidgetKit: серия и тренировки за сегодня, данные через App Group |
| App Intents | По желанию | «Записать подход» из Шорткатов и Siri |

**Готово, когда:** все обязательные пункты сделаны, плюс хотя бы один из HealthKit или виджета: интеграция с системой хорошо выделяет проект.

## Этап 7 — Упаковка для портфолио (~1–2 вечера)

Рекрутер тратит на репозиторий пару минут, поэтому README важнее, чем кажется.

- [ ] README: одна строка о том, что это, GIF с демо (запись → достижение → вопрос Отису), 4–5 скриншотов, стек технологий, требования (iOS 26, устройство с Apple Intelligence для Отиса).
- [ ] Раздел «Архитектура»: короткая схема (модели → сервисы → экраны) и 2–3 решения с объяснением «почему». Например: достижения считаются из данных, а не хранятся; AI работает on-device.
- [ ] Раздел «История»: курсовая 2024 → переписано в 2026, ссылка на тег `v1-coursework`. Рост за два года — хорошая тема для собеседования.
- [ ] Тесты на `StatsService` и `AchievementEngine` проходят. GitHub Actions со сборкой и тестами — по желанию, но зелёный бейдж смотрится хорошо.
- [ ] Релиз `v2.0` на GitHub, репозиторий закреплён в профиле, ссылка в резюме.
- [ ] TestFlight — если есть платный аккаунт разработчика. Иначе хватит видео в README.

Итого примерно 17–20 вечеров. При 2–3 вечерах в неделю это 6–8 недель. Если понадобится раньше, этапы 0–4 уже дают готовое приложение без AI, и его уже можно показывать.
